# AI 视频翻译（Voice Translation Lab）实现说明

版本：3.9.37

## 功能边界

用户上传原片视频 → 上传自己的声音样本 → 本地克隆成「我的声音」→ 选择该声音
→ 把原片人声换成「用我的声音说目标语言」→ 输出成片。

- 只换人声，不做口型重绘（口型对齐仍在「AI多语口播」里，避免重复 5 倍实时开销）。
- 目标语言与原片语言相同时，不做翻译，只做「换声」。
- 视频画面默认无损直拷（`-c:v copy`）；开启「烧录字幕」时才重编码并叠加 libass 字幕。
- 成片固定为「一条画面 + 一条音轨」，音轨 = 克隆配音（可选保留原片 BGM，侧链闪避）。
- 全离线：Whisper.cpp 识别、Llama.cpp 翻译、Chatterbox 克隆合成、ffmpeg 封装，
  不调用任何第三方模型 API。

## 3.9.29 连续语流（修复「断断续续 / 不自然」）

**根因**（三条同时作用于听感，改一条不够）：

1. 逐句克隆 = 每句从零起调，句尾降调、句首重音重置，句子越短越像念稿；
2. 生成上限按「字幕窗口 × 1.5」算，译文一长就被 token 上限在**句中截断**（实测同一段
   55 字中文只出 5.3 秒语音，后半句直接没了）；
3. 为塞回窗口对每句单独 `atempo`（≤1.25），到上限仍在窗口末尾淡出硬切，词尾被削。

**改法**：

- 相邻短句并成「语段」（停顿 ≤0.4s、总长 ≤84 字、跨度 ≤9s）再合成：句调完整、不再句中截断；
  字幕条目保持原样，逐条按字位比例重映射到实际语音时间。
- token 上限改成「按语速估语音时长 × 25 token/秒 × 1.35」；墙钟上限同步放宽（克隆约 22 倍实时）。
- 时间轴：语段起点落回原片位置（配音跟得上画面），语音超长才顺延；
  超出片长只做**一次**整片变速（≤1.35），还放不下才压缩气口（最小 0.08s）。
- 每段合成后裁掉首尾 -45dB 以下静音（TTS/克隆都会在文件尾垫几百毫秒），
  避免「底噪 + 气口」叠成一处明显空档；句内气口全部保留。
- 电平仍用 `segmentGain`（整句 LUFS 归一 + 噪底封顶 -34dB + 相邻句台阶 ±3dB），不逐句泵动。

**实测（2026-11-04，13.84 秒英文原片 + 本机真人声音样本，翻译成中文）**：

- 成片视频 1 条 / 音轨 1 条、时长 13.84s（与原片一致），warning 为空（无需整片变速）；
- 成片语音覆盖 0–12.36s，唯一静音段是片尾 12.36–13.86（1.50s），**语音区间内无 ≥0.8s 硬静音**；
- 回环 Whisper（中文）识别出 55 个汉字，语义完整、无半句：

  > 你好,大家,今天我想展示给你三个简单的事情首先保持你的桌面整洁其次,计划好你的一天在开始之前最后,至少恢复一下你做的事

- 同一条链路在修复前（3.9.28）同一素材只合成出 5.3 秒语音（后半句被 token 上限截断），
  片尾静默 8.5s；回环 ASR 只剩前 29 个汉字。

## 3.9.37 消除「呲呲呲」嘶声、把清晰度拉回真人水平

用户反馈：①成片还有「呲呲呲」的噪音 ②声音不够清晰、瑕疵多，要媲美真人。
本轮先用真实克隆引擎（`worker.py` + `vmw22d794wtc9/ref.wav`）合成同一条句子，
把 24k 原始合成音 → 24k→44.1k 重采样 → `suppressNoise` → 清洁链，逐段做频谱测量，
再把每一处改动单独复测。**没有换克隆模型**（换底座要重下 2GB 权重、重装依赖，
而且实测问题不在模型本身），换的是降噪算法与整条清洁链。

### 一、根因（全部有实测）

| # | 根因 | 实测证据 | 听感 |
| --- | --- | --- | --- |
| 1 | 谱减法产生金属嘶声 | 降噪后 4.8~11k 的逐帧能量标准差从 **15.6dB 抬到 19.3dB（+24%）**；谱平坦度同步升高 | 「呲呲呲」的随机尖峰是降噪器自己造的 |
| 2 | 噪声底被「轻声的字」污染 | 气口实测 -66dBFS、语音 -18dBFS，旧门限 `语音-12dB=-30dB` 把大量轻声字算进 N(f)；维纳增益在语音段只剩 **-3.6dB** | 整句被削薄、发闷 |
| 3 | 清洁链把清晰度频段连削两次 | 旧版 4 级窄带（2100/3000/4300/6200Hz，各 -3~-4.5dB）叠加后实测 2.5~3.5k **-8.1dB**、3.5~4.8k **-7.9dB**、4.8~6k **-9.5dB** | 闷、糊、不清晰 |
| 4 | 克隆音本身高频就偏暗 | 同一语音 vs 12 秒真人参考：4.8~6k 差 **7.9dB**、6~8k 差 **9.5dB**、8~11k 差 **11.7dB** | 不像真人、没有「气声/齿音」 |
| 5 | 整帧电平斜坡起点过低 | 474 帧里 **97 帧**落在 8~18dB 斜坡，中位帧被压约 **9dB** | 吞轻声字、不清晰 |
| 6 | 配乐降噪逐帧跟踪噪声底 | `afftdn tn=1` 在音乐上按帧改噪声谱；3.9.36 把伴奏抬到 -26 LUFS 后这层残渣第一次可闻 | 伴奏里有「呲呲」噪点 |

### 二、改动

| 改动 | 文件 | 实测结果 |
| --- | --- | --- |
| 谱减 `1-2.5·N/P` → 决策引导维纳 `xi/(1+xi)`（`DD_ALPHA=0.90`、5 点频域平滑），增益地板 -40 → **-24dB** | `electron/denoise.js` | 4.8~11k 逐帧抖动 19.3 → **16.5dB**（原始合成音 15.6），谱平坦度回到与原始一致；不再有随机尖峰 |
| 噪声候选帧加「噪底闸」：`thr = min(语音-12dB, 噪底+8dB)` | `electron/denoise.js` | 语音段频带倾斜回到与原始合成音一致（4.8~11k 由 -28.6 回到 -27.9，原始 -27.0），不再整句削 3.6dB |
| 整帧斜坡 `GATE_START_DB` 8 → **14**、`GATE_FULL_DB` 18 → **26** | `electron/denoise.js` | 正常句内动态（12~18dB）不再被当噪声；气口仍在 25dB 以下，166 帧照样压到底 |
| `CLEAN_SHELF` 4 级削中高频 → `highshelf 5200Hz +8dB`、`highshelf 8500Hz +4dB` + 单个 6.2k/Q1.6 的 **-2dB** 去齿音 | `electron/localize.js` | 与真人参考的频带差：4.8~6k 7.9 → **3.8dB**、6~8k 9.5 → **4.1dB**、8~11k 11.7 → **4.9dB**；2.5~4.8k 不再被削 8dB |
| `BGM_CLEAN` 的 `afftdn` `nr=20:nf=-52:tn=1` → `nr=10:nf=-55:tn=0` | `electron/localize.js` | 固定噪声底、增益不随帧跳，伴奏不再被切成一段段残渣 |

### 三、为什么不动声码器步数

同一句话 12 步 vs 20 步实测：声码器耗时 16.46s → 21.38s（**+30%**），
而高频倾斜/抖动没有稳定的客观改善（两次采样文本不同，差异被内容掩盖）。
在 3.9.35 才刚按用户要求做过提速的前提下，为不确定的收益再加 30% 声码器时间不划算，
所以步数保持 12；本轮的质量提升全部来自「降噪算法 + 噪声底估计 + 清洁链」。
如果后续要换底座，优先级应是 44.1kHz 声码器的克隆模型，而不是加步数。

## 3.9.36 修好背景音乐、音量稳定、AI 发音

用户反馈：①声音忽大忽小 ②中文里的 AI 读错 ③朗读时没有背景音乐 ④人声不够清晰。
四条里三条同一个根因。

### 一、根因

`dubAudioChain` 的侧链闪避参数是 `threshold=0.004`（≈-48dBFS）、`ratio=6`。
配音 RMS 约 0.125、峰值 0.9，扣掉 `level_sc` 后仍远高于阈值 → 侧链把伴奏压到
**-30dB 以下**（用正弦素材实测），于是：

- 朗读段：伴奏几乎消失 → 用户听到「朗读时没有背景音乐」；
- 句间：伴奏整块回来 → 整片听感就是「声音忽大忽小」。

叠加 `BGM_TARGET_LUFS = -31`（比配音 -18 LUFS 低 13 LUFS，本身就极轻），
即使不闪避也几乎听不见。

### 二、改动

| 改动 | 文件 | 实测/依据 |
| --- | --- | --- |
| `BGM_DUCK` 改为 `threshold=0.02:ratio=3:attack=18:release=480:level_sc=0.6` | `electron/localize.js` | 正弦素材实测：伴奏 -27.1 → -34.8 dBFS，**只后退 7.7dB**；旧参数掉 30dB+ |
| `BGM_TARGET_LUFS` -31 → -26；抬升上限 +2 → +6dB | `electron/localize.js` | 句间音乐清楚可闻，朗读时人声仍比伴奏高 15 LUFS 以上 |
| `AGC_GAIN_SEC` 0.1 → 0.28s（`AGC_MAX_DB` 保持 9） | `electron/denoise.js` | 0.1s 时增益追着每个音节跑，是句内「忽大忽小」的来源；放慢后只修整句级漂移 |
| 新增 `CJK_ACRONYM`，zh 下整词 `AI` → `人工智能` | `electron/localize.js` | 「诶」是多音字（éi/èi/ǎi），克隆音常读成「哎」；AIGC/OpenAI 因整词边界判断不受影响 |

### 三、为什么这样改而不是加 EQ

「人声不清晰」主要是伴奏在句间过响、句中又消失造成的听觉对比失衡；
把伴奏抬到 -26 LUFS 并用 7.7dB 的温和闪避，语音与伴奏稳定保持 15 LUFS 差距，
清晰度自然回升。给克隆音额外挂 EQ 会改变音色，风险大于收益，故未做。

## 3.9.35 配音提速（不牺牲音质，实测驱动）

### 一、先量清楚，再动手

用常驻 worker 直接跑单句基准（Apple Silicon / Metal，同一句 32 字中文，`VC_STEPS=12`）：

| 指标 | 实测值 |
| --- | --- |
| 自回归 token 生成 / 声码器解码 | **87% / 13%** |
| 单 worker 聚合吞吐（conc 1 / 3 / 5） | 6.1 / 5.4 / 6.2 token/s（噪声内持平） |
| 单句首句完成时间（conc 1 / 3 / 5） | 约 40s / 126s / 133s |
| 关掉 CFG（cfg 0.5→0） | 提速 **0%**（MPS 单步是 kernel 延迟瓶颈，batch=2 几乎不增成本） |
| 声码器 12→10 步 | 解码 −16%，**总时长仅 −5%** |
| CPU 与 GPU 双进程并行 | 稳态聚合 **+30%~60%**（GPU 基本不掉速） |
| 并行时 swap | 1.7GB → 12~16GB（16GB 机器），CPU 侧被换页拖慢 23~47% |

结论：真正的大头是 **token 生成**，不是声码器；**加并发不提吞吐、只拉长单句延迟**；
**GPU 饱和时 CPU 核是空的** —— 这才是可用的增量算力。

### 二、改动

| 改动 | 文件 | 效果 |
| --- | --- | --- |
| 空闲内存 ≥5GB 时后台起一个 `device=cpu` 副 worker（2 线程 / 2 并发），与 MPS 主引擎按句轮转分担 | `electron/voicelocal.js`（`openSession` 新增 `device`）、`electron/localize.js`（`startTranslate`） | 稳态吞吐 +30%~60%，模型/采样参数/步数全不变 |
| `LOCAL_CONC` 5→2（三入口统一）；并发上限改为「各会话并发之和」 | `electron/localize.js` | 总时长不变，单句延迟降到 1/3，首句从 2 分钟变成 40 秒级 |
| 副 worker 起不来（内存不足/加载失败）静默回落单路 | `electron/localize.js` | 不影响出片，只在日志留一行原因 |
| 会话重建按槽位恢复设备（`devices: ['auto','cpu']`） | `electron/localize.js` | 副 worker 重建后不会又变成第二个 MPS |
| `flowNarrationForTest` 并发 5→2 | `electron/localize.js` | 自动化测试与生产配置一致 |

### 三、为什么没动这些（都被实测否掉）

- **CFG 不关**：关掉提速 0%，却会丢掉音色/口音控制。
- **声码器步数不回退 12→10**：只省 5% 总时长，代价是波形顺滑度回退（3.9.34 刚换来的音质）。
- **`max_tokens` 不收紧**：同一句自然收尾在 154~307 token 间波动，收紧会切掉正常句尾
  （用户痛点「有字幕没声音」）；而且撞上限时 worker 的 `truncated` 仍为 false，
  收紧只会把「跑飞」从 cap 换成重试，更慢。
- **CPU 副 worker 不做无条件常驻**：16GB 机器一次并行就把 swap 打到 12~16GB，
  收益会被换页吃光（实测有一轮 −4%），所以必须看 `os.freemem() ≥ 5GB`。

## 3.9.34 任务锁自愈 + 音质再提升（顺滑 / 清晰 / 有换气）

### 一、误报「已有任务进行中，请稍候」

病根：三个重任务入口（AI 多语切片 `start`、AI 多语口播 `startOral`、AI 视频翻译
`startTranslate`）共用一把全局锁 `activeJob`，旧实现只在各自的 `finally` 里清锁：

- 只要有一个 `await` 永远不返回（克隆 worker 失联、模型下载卡住、界面重载后再没人
  发进度、点过「停止」但子进程没死透），`finally` 就永远不会执行，锁永久挂着；
- `makeJobDir()` 等初始化在 `try` 之前，抛错直接留下死锁；
- 试听入口（`previewVoice` / `previewProfile`）同样只读 `activeJob`，一样被卡住。

于是界面明明空闲，点「开始翻译并换声」却被拒绝。

做法（`localize.js`）：

1. 锁升级为带时间线的作业对象：`{ kind, startedAt, tick, phase, done, watch }`；
   `touchJob(phase)` 在每个进度回调里刷新 `tick`（`emit` 统一包一层 `withTouch`）。
2. `acquireJob(kind)` 同步占锁，占之前先等旧作业收尾最多 2.5 秒；锁的
   `tick` 超过 10 分钟没动就判定陈旧，`forceReleaseJob()` 先按取消处理
   （杀子进程、abort 下载、关克隆会话、取消口型）再清锁；真被占用时报错写明
   「哪条任务 · 哪个阶段」，用户能对上号。
3. 每个作业自带 30 秒一次的看门狗，同一判据兜底。
4. `makeJobDirFor(job)`：建临时目录失败时立刻放锁。
5. `cancel()` 增加 4 秒兜底：用户点停止后作业没在 4 秒内收尾就强制清锁，
   可以立刻重新开始。
6. 试听入口改用 `assertJobIdle()`，陈旧锁同样会自动释放。

### 二、成片声音仍不够自然 / 断断续续 / 不够清晰

| 改动 | 旧值 | 新值 | 依据 |
| --- | --- | --- | --- |
| 声码器 flow-matching 步数 | 8 | 12 | 8 步仍带颗粒感与沙沙底噪；12 步波形明显顺滑，解码耗时约 ×1.5，生成仍占大头 |
| 句内气口折叠门限 | 低于语音 26dB、连续 0.26s、保留 0.15s | 低于语音 30dB、连续 0.45s、保留 0.30s | 0.2~0.4s 是真人逗号换气，压到 0.15s 会让朗读又赶又平；26dB 还会误吃轻声辅音 |
| 合成文本句末标点 | 原样 | 缺标点时补「。」/「.」 | 字幕常停在半句，克隆模型靠句末标点收尾降调，缺标点会一路拖音、读成「没说完」 |
| 翻译提示 | 只约束口音风格 | 加「时长贴近原文、宁短勿长」 | 中译外通常变长，成片只能靠 atempo 整体加速，越快越不清 |

三处入口的 `LOCAL_STEPS` 与试听同步改为 12，听到的试听效果与成片一致；
`ensureTerminal()` 只补标点、不增删文字，字幕仍用原译文。

## 3.9.33 跨语言配音口音收敛（标准美式英语 / 各语言通用口音）

### 病根：CFG 引导把参考音的「源语言口音」一起搬进目标语言

克隆引擎（Chatterbox 多语）里，`cfg_weight` 是分类器无关引导的强度。参考音是中文
（口播/VT 用的是原片说话人的嗓音）时，模型会沿着参考音的发音习惯「续写」目标语言，
CFG 越强，口音越明显——成片英语听起来像带印度腔，法语/西语也会带中文调。官方 README
给的做法很直接：参考音与目标语言不一致时，把 CFG weight 设为 0。

### 做法

1. `makeLocalSynth({ ctx, langId, crossLang })`：`crossLang = (目标语言 ≠ 原片语言)` 时
   `cfgWeight = 0.3`，同语言仍为 `0.5`（保持原声贴合）。三个配音入口（AI 多语切片、
   AI 多语口播、AI 视频翻译）都已接上。
   为什么不用官方建议的 0：实测同一句 102 字英文，cfg 0 / 0.2 都跑满 200 token、
   时长 8.0s（语速掉约 30%），0.5 是 152 token / 6.04s，0.3 是 155 token / 6.16s。
   cfg 0 会让整片被 atempo 追着加速 1.2~1.35 倍，反而更不自然，所以取 0.3：
   引导强度降到原来的 60%，语速与原来一致。
2. `voicelocal.speak()` 把 `cfgWeight` 透传成消息字段 `cfg_weight`；
   `worker.py` 按句读取（`0~1` 夹紧），只有与默认 0.5 不同才写进 `generate()`
   ——多句并发时每句各自带自己的 cfg，不共享全局状态。
3. 翻译提示按目标语言加了风格约束：英语要求「地道、口语化的美式英语（General American）、
   用常见缩略形式、不要书面腔和逐字直译」；日语（东京腔）、韩语（首尔腔）、
   西语（中性通用）、葡语（通用巴西）、法语、德语各给一条标准口语约束，
   避免译文本身带书面腔或直译腔，进一步压低「非母语感」。

### 效果

- 跨语言片段不再被参考音的中文发音牵着走，目标语言按模型通用发音生成；
- 同语言（如原片就是英语、只做字幕）仍用 0.5，音色与原声贴合度不变；
- 口音是主观听感，客观侧验证：worker 能按句收到 `cfg_weight`、并真正传入
  `generate()`（单测覆盖），实机合成在 cfg=0 下不报错、时长正常。

## 3.9.32 AI 多语口播取消 120 秒片长限制

口播流程原来有两道 120 秒闸门，都会让用户「传了长片却出不了片」：

1. `probe` 后 `info.duration > ORAL_MAX_SEC + 0.5` 直接抛错「口播视频请控制在 120 秒以内」；
2. 即使侥幸通过，`dur = Math.min(info.duration, ORAL_MAX_SEC)` 会把超过 120 秒的部分**静默截断**。

3.9.32 把这两处一起删掉：`ORAL_MAX_SEC` 常量移除，`dur` 直接取整片时长
（`Math.max(0.5, info.duration)`），识别、翻译、克隆配音、口型重绘、混音与自检全部按整片跑。
上传提示同步从「建议 1 分钟以内……（最长 2 分钟）」改为「片长不限（口型按帧重绘，片越长耗时越久）」，
不再与行为矛盾。口型按帧重绘，片长与耗时仍近似线性，进度条会如实推进。

回归断言：`test/unit.js` 新增「AI 多语口播不再限制片长」——源码不得再出现 `ORAL_MAX_SEC` 与 120 秒拒绝文案，
`dur` 必须取 `info.duration`，上传提示不得再写「最长 2 分钟」。

## 3.9.31 句内响度拉平 / 连读收口 / 字幕必被朗读（第二轮迭代）

3.9.30 修好的是「句与句之间」的水位和「整句被截断」，真机上剩下的四个问题全部落在
**句子内部**和**时间轴**上：

### ① 忽大忽小：克隆引擎句内慢漂移，逐句增益管不到

逐句固定增益只能把每句对齐到同一水位，句内仍是「前半句响、后半句突然轻」——
这是克隆模型的慢包络漂移，不是噪声也不是截断。

新增 `denoise.flattenLevel(pcm, rate, opts)`，接在降噪与气口折叠之后：

- 20ms 帧 / 10ms 帧移求帧电平 dB，`speech = p90(所有帧)`；
- 包络 = `movingAvg(medianFilter(lv, 7), 45 帧 ≈ 450ms)` —— 先 7 帧中值去尖峰，
  再 450ms 均值只保留「慢漂移」，咬字起伏不被抹平；
- 只对 `lv ≥ speech-34` 的语音帧算 `gain = clamp(speech - env, ±9dB)`，气口帧增益固定 1
  （不把噪声一起抬起来）；
- 增益再做 100ms 均值平滑，样本按线性插值应用，避免逐帧台阶。

### ② 仍断断续续：气口折叠只认数字静音

3.9.30 的 `tightenPauses` 判据是 `|v| < 1e-3`（约 -60dBFS），而降噪只会把
「低于语音 15dB 且 ≥350ms」的深静音拉零；-50~-40dBFS 的中等气口原样留下，
听感就是「一句一断」。

改为相对门限：帧电平 `< speech - 26dB` 且连续 `≥ 0.26s` 的气口折到 `0.15s`，
语音样本一个不动（仍按 run 搬移样本，不做重采样）。

### ③ 字幕没被朗读 / 对不齐：token 上限与语段过长

- 合成后检查 `wavDuration(raw) < needSec`（`needSec = max(0.35, chars/(CJK?7:22)*0.8)`），
  或引擎回报 `truncated`，就用 `min(1400, max(maxTokens+64, maxTokens*1.8))` 重生成一次；
  系统音色路径同样按 `wavDuration < needSec` 重合成。
- `groupForFlow` 合并上限从 84 字 / 9s 收到 **60 字（CJK）/ 120 字符，≤8s**，
  减少「长段按字位比例摊字幕」造成的对齐漂移。

### ④ 整体质感：片短于配音时不再一律放慢

旧逻辑只要配音比片子长就 atempo 放到 0.90，咬字发黏、拖长。
现在先把富余时长摊进气口，气口最多 0.55s（再长又是一句一断），
`MIN_TEMPO` 抬到 **0.94** 且仅在仍超长时才启用；实在放不下才按比例压缩气口到 0.08s。

### 实测（2026-11-05，18s 中文成片，3 句含 AI 与长文本）

- `tempo 1.001`（几乎 1:1，不再是 0.90）；`tailSilenceSec 0`；
- 三句 `cueLevels [-17.1, -17.3, -17.2]`，句间差 **0.2dB**；
- 语音帧 `p10p90 8.4dB` / `maxDrop 10dB`（句内自然起伏，无台阶）；
- `holes []`：语音区间无 ≥0.8s 硬静音；
- `npm test` 35 项全绿、`npm run test:smoke` PASSED（含「语音区间内无 0.8s 以上硬静音」断言）。

## 3.9.30 四问题彻底修复（噪音 / 忽大忽小 / AI 读错 / 仍不连贯）

3.9.29 把逐句克隆改成了连续语流，但真机上仍能听出四个问题。逐条定位到的**根因都不是
「参数没调好」，而是判据用错了**：

### ① 噪音：句尾低频闷响被当成语音留下来

克隆模型在句尾经常不输出 EOS，把 token 上限跑满：实测 14 字中文给 142 token 上限 →
生成 5.68s，而真语音只有约 1.9s，后 3.2s 是 100~300Hz、-30~-55dBFS 的液压闷响。
`denoise.js` 的句尾切点只看电平（本句语音 -14dB 以内），闷响只比语音低十几 dB，
判据一路把切点推到 5.68s，于是音乐床 + 闷响一起进成片。

改法：帧能量之外再算一条**一阶差分（+6dB/oct 高通）**能量，切点同时要求
「电平 ≥ speechRef-17」且「高通 ≥ hpRef-24」，两条都做 5 帧中值平滑。
闷响几乎没有 500Hz 以上能量，轻声收尾的人声正常，一测就分开。

实测：切点 5.68s → 2.35s（中间产物 `0.wav` 5.68s、`0-trim.wav` 1.73s），
成片气口噪底 -77.5dBFS / 峰 -48.3dBFS，末段后为数字静音。

### ② 忽大忽小：短句噪底误判触发噪声封顶

`measureSegment` 用 `astats` 的 `at(0.12)` 取噪底。wav 帧是 4096 样本 = 93ms，
1.5s 的短句只有 17 帧，12% 位置落在**语音段中间**，读到 -29dB；
`GAIN_NOISE_CEIL - floor` 于是把该句增益从 +3.4dB 砍到 -8.4dB，比邻句轻 11dB。
这与「逐句 LUFS 归一」本身没错，是噪底判据错。

改法：`asetnsamples=n=1024`（23ms 帧，1.5s 有 64 帧），噪底改成
「低于语音 12dB 的帧的中位数，且至少 4 帧」；`segmentGain` 改为
`TARGET_SPEECH_DB(-15.5) - speech`，删掉 ±3dB 跨句台阶与 `prevGain`；
整轨出片前再 `normalizeTrack` 收口到 -18 LUFS（±6dB 内）。

实测（3 段中文、含 2.6s/2.2s 长停顿）：`cueLevels [-13.9, -12.9, -14.0]`，
句间差 **1.1dB**（修复前同一素材 11.2dB / 三档 -23.2、-12.8、-12.0）。

### ③ AI 读错：中文 language_id 把拉丁缩写按拼音念

Chatterbox 给 `language_id=zh` 时，模型看到 "AI" 会念成拼音的 "ai"（一声），
听起来像「哎」。字幕里写 "AI"、配音里念「哎」，中英混读全毁。

改法：新增 `speakableText(text, langId)`，中文/日文/韩文里把
**独立出现的全大写拉丁缩写**按字母名展开再送给引擎（AI → 诶艾 / エーアイ / 에이아이），
字幕仍用原文。正则是 `(^|[^A-Za-z0-9])(\d*)([A-Z]{1,})(?![A-Za-z0-9])`，
所以 `OpenAI`、`iPhone`、`TikTok`、`ChatGPT` 这类混成词不转，英文语种整段不转。

实测（同一句 4 种写法，`0-trim.wav` 时长）：`AI` 1.93s、`诶艾` 2.67s、
`人工智能` 2.92s —— 展开后的时长与 4 音节词同量级，确认被完整读出而不是被吞。
（ASR 回环无法验证发音，本机未装 whisper 引擎。）

### ④ 仍不连贯：长停顿被原样搬进成片，句内死气口也没收

3.9.29 把语段起点锚回原片位置、语段之间"沿用原片停顿"，原片 2.6s 的换气被原封不动
搬进成片 → 听感依旧一句一断；克隆句内的死气口（≥0.22s，|v|<1e-3）也留着。

改法：
- 布局改为**连续语流**：`pauses[i] = clamp(原片 gap, 0.12, 0.5)`，语段顺次接排，
  只有首段起点仍对齐原片（≤0.2s）；
- `tightenPauses` 把句内 ≥0.22s 的死气口折叠到 0.14s，语音样本一个不动；

## 3.9.39 多语口播 / 视频翻译接入多语言（默认英文）

### 问题

用户切到 English 后，侧边栏「AI 多语口播」「AI 视频翻译」以及整个视频翻译页面仍是中文：
大标题「用我自己的声音，把这条片子的语言换掉。」、说明文字、流程节点「原片 / 我的声音 / 成片」、
「检查中」「Whisper 识别」、预计耗时等全部写死。根因不是默认语言配置（`detect()` 早已默认
`FALLBACK = 'en'`），而是：

1. 这两个视图的静态文案在 `src/i18n/*.js` 里**没有词条**，词表 key 就是中文原文，缺 key 时
   `translate()` 原样回落中文。
2. `src/translate.js`、`src/oralcast.js` 里 `T(` 调用数为 0，动态拼接的文案（`原片 00:18 × 7 个语种
   ≈ …`）永远无法与词表精确匹配。

### 改动

- 补齐词表：7 份语言包各新增 149 条（147 条页面/动态文案 + 「无音轨」「声音」），
  key 与页面中文原文逐字一致，全部落在文件末尾新增批次。
- 大标题被 `<em>` 拆成四个文本节点（`用` / `我自己的声音` / `，` / `把这条片子的语言换掉。`），
  按片段给出可拼接译文：en `Use ` + `my own voice` + `, ` + `swap this video’s language.`；
  de `Mit ` + `meiner eigenen Stimme` + `` + `, tausche ich die Sprache dieses Videos aus.`；
  ja `` + `自分の声で` + `` + `この動画の言語を丸ごと入れ替える。`
- `translate.js` / `oralcast.js` 增加 `T()` 包装，把 23 处模板拼接改为占位符：
  预计耗时、引擎安装状态、声音库错误、删除/保存提示、试听提示、运行副标题、完成提示、
  剩余时间、确认弹窗（拆 3 段用 `\n\n` 连接）、产出 Toast。
- `app.js` 侧边栏 Pro 提示改用 `window.T('{0}（Pro 专属）', …)`。
