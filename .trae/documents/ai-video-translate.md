# AI 视频翻译（Voice Translation Lab）实现说明

版本：3.9.29

## 功能边界

用户上传原片视频 → 上传自己的声音样本 → 本地克隆成「我的声音」→ 选择该声音
→ 把原片人声换成「用我的声音说目标语言」→ 输出成片。

- 只换人声，不做口型重绘（口型对齐仍在「AI多语口播」里，避免重复 5 倍实时开销）。
- 目标语言与原片语言相同时，不做翻译，只做「换声」。
- 视频画面默认无损直拷（`-c:v copy`）；开启「烧录字幕」时才重编码并叠加 libass 字幕。
- 成片固定为「一条画面 + 一条音轨」，音轨 = 克隆配音（可选保留原片 BGM，侧链闪避）。
- 全离线：Whisper.cpp 识别、Llama.cpp 翻译、Chatterbox 克隆合成、ffmpeg 封装，
  不调用任何第三方模型 API。

## 3.9.29 连续语流（修复「断断续续 / 不自然」）

**根因**（三条同时作用于听感，改一条不够）：

1. 逐句克隆 = 每句从零起调，句尾降调、句首重音重置，句子越短越像念稿；
2. 生成上限按「字幕窗口 × 1.5」算，译文一长就被 token 上限在**句中截断**（实测同一段
   55 字中文只出 5.3 秒语音，后半句直接没了）；
3. 为塞回窗口对每句单独 `atempo`（≤1.25），到上限仍在窗口末尾淡出硬切，词尾被削。

**改法**：

- 相邻短句并成「语段」（停顿 ≤0.4s、总长 ≤84 字、跨度 ≤9s）再合成：句调完整、不再句中截断；
  字幕条目保持原样，逐条按字位比例重映射到实际语音时间。
- token 上限改成「按语速估语音时长 × 25 token/秒 × 1.35」；墙钟上限同步放宽（克隆约 22 倍实时）。
- 时间轴：语段起点落回原片位置（配音跟得上画面），语音超长才顺延；
  超出片长只做**一次**整片变速（≤1.35），还放不下才压缩气口（最小 0.08s）。
- 每段合成后裁掉首尾 -45dB 以下静音（TTS/克隆都会在文件尾垫几百毫秒），
  避免「底噪 + 气口」叠成一处明显空档；句内气口全部保留。
- 电平仍用 `segmentGain`（整句 LUFS 归一 + 噪底封顶 -34dB + 相邻句台阶 ±3dB），不逐句泵动。

**实测（2026-11-04，13.84 秒英文原片 + 本机真人声音样本，翻译成中文）**：

- 成片视频 1 条 / 音轨 1 条、时长 13.84s（与原片一致），warning 为空（无需整片变速）；
- 成片语音覆盖 0–12.36s，唯一静音段是片尾 12.36–13.86（1.50s），**语音区间内无 ≥0.8s 硬静音**；
- 回环 Whisper（中文）识别出 55 个汉字，语义完整、无半句：

  > 你好,大家,今天我想展示给你三个简单的事情首先保持你的桌面整洁其次,计划好你的一天在开始之前最后,至少恢复一下你做的事

- 同一条链路在修复前（3.9.28）同一素材只合成出 5.3 秒语音（后半句被 token 上限截断），
  片尾静默 8.5s；回环 ASR 只剩前 29 个汉字。

## 3.9.32 AI 多语口播取消 120 秒片长限制

口播流程原来有两道 120 秒闸门，都会让用户「传了长片却出不了片」：

1. `probe` 后 `info.duration > ORAL_MAX_SEC + 0.5` 直接抛错「口播视频请控制在 120 秒以内」；
2. 即使侥幸通过，`dur = Math.min(info.duration, ORAL_MAX_SEC)` 会把超过 120 秒的部分**静默截断**。

3.9.32 把这两处一起删掉：`ORAL_MAX_SEC` 常量移除，`dur` 直接取整片时长
（`Math.max(0.5, info.duration)`），识别、翻译、克隆配音、口型重绘、混音与自检全部按整片跑。
上传提示同步从「建议 1 分钟以内……（最长 2 分钟）」改为「片长不限（口型按帧重绘，片越长耗时越久）」，
不再与行为矛盾。口型按帧重绘，片长与耗时仍近似线性，进度条会如实推进。

回归断言：`test/unit.js` 新增「AI 多语口播不再限制片长」——源码不得再出现 `ORAL_MAX_SEC` 与 120 秒拒绝文案，
`dur` 必须取 `info.duration`，上传提示不得再写「最长 2 分钟」。

## 3.9.31 句内响度拉平 / 连读收口 / 字幕必被朗读（第二轮迭代）

3.9.30 修好的是「句与句之间」的水位和「整句被截断」，真机上剩下的四个问题全部落在
**句子内部**和**时间轴**上：

### ① 忽大忽小：克隆引擎句内慢漂移，逐句增益管不到

逐句固定增益只能把每句对齐到同一水位，句内仍是「前半句响、后半句突然轻」——
这是克隆模型的慢包络漂移，不是噪声也不是截断。

新增 `denoise.flattenLevel(pcm, rate, opts)`，接在降噪与气口折叠之后：

- 20ms 帧 / 10ms 帧移求帧电平 dB，`speech = p90(所有帧)`；
- 包络 = `movingAvg(medianFilter(lv, 7), 45 帧 ≈ 450ms)` —— 先 7 帧中值去尖峰，
  再 450ms 均值只保留「慢漂移」，咬字起伏不被抹平；
- 只对 `lv ≥ speech-34` 的语音帧算 `gain = clamp(speech - env, ±9dB)`，气口帧增益固定 1
  （不把噪声一起抬起来）；
- 增益再做 100ms 均值平滑，样本按线性插值应用，避免逐帧台阶。

### ② 仍断断续续：气口折叠只认数字静音

3.9.30 的 `tightenPauses` 判据是 `|v| < 1e-3`（约 -60dBFS），而降噪只会把
「低于语音 15dB 且 ≥350ms」的深静音拉零；-50~-40dBFS 的中等气口原样留下，
听感就是「一句一断」。

改为相对门限：帧电平 `< speech - 26dB` 且连续 `≥ 0.26s` 的气口折到 `0.15s`，
语音样本一个不动（仍按 run 搬移样本，不做重采样）。

### ③ 字幕没被朗读 / 对不齐：token 上限与语段过长

- 合成后检查 `wavDuration(raw) < needSec`（`needSec = max(0.35, chars/(CJK?7:22)*0.8)`），
  或引擎回报 `truncated`，就用 `min(1400, max(maxTokens+64, maxTokens*1.8))` 重生成一次；
  系统音色路径同样按 `wavDuration < needSec` 重合成。
- `groupForFlow` 合并上限从 84 字 / 9s 收到 **60 字（CJK）/ 120 字符，≤8s**，
  减少「长段按字位比例摊字幕」造成的对齐漂移。

### ④ 整体质感：片短于配音时不再一律放慢

旧逻辑只要配音比片子长就 atempo 放到 0.90，咬字发黏、拖长。
现在先把富余时长摊进气口，气口最多 0.55s（再长又是一句一断），
`MIN_TEMPO` 抬到 **0.94** 且仅在仍超长时才启用；实在放不下才按比例压缩气口到 0.08s。

### 实测（2026-11-05，18s 中文成片，3 句含 AI 与长文本）

- `tempo 1.001`（几乎 1:1，不再是 0.90）；`tailSilenceSec 0`；
- 三句 `cueLevels [-17.1, -17.3, -17.2]`，句间差 **0.2dB**；
- 语音帧 `p10p90 8.4dB` / `maxDrop 10dB`（句内自然起伏，无台阶）；
- `holes []`：语音区间无 ≥0.8s 硬静音；
- `npm test` 35 项全绿、`npm run test:smoke` PASSED（含「语音区间内无 0.8s 以上硬静音」断言）。

## 3.9.30 四问题彻底修复（噪音 / 忽大忽小 / AI 读错 / 仍不连贯）

3.9.29 把逐句克隆改成了连续语流，但真机上仍能听出四个问题。逐条定位到的**根因都不是
「参数没调好」，而是判据用错了**：

### ① 噪音：句尾低频闷响被当成语音留下来

克隆模型在句尾经常不输出 EOS，把 token 上限跑满：实测 14 字中文给 142 token 上限 →
生成 5.68s，而真语音只有约 1.9s，后 3.2s 是 100~300Hz、-30~-55dBFS 的液压闷响。
`denoise.js` 的句尾切点只看电平（本句语音 -14dB 以内），闷响只比语音低十几 dB，
判据一路把切点推到 5.68s，于是音乐床 + 闷响一起进成片。

改法：帧能量之外再算一条**一阶差分（+6dB/oct 高通）**能量，切点同时要求
「电平 ≥ speechRef-17」且「高通 ≥ hpRef-24」，两条都做 5 帧中值平滑。
闷响几乎没有 500Hz 以上能量，轻声收尾的人声正常，一测就分开。

实测：切点 5.68s → 2.35s（中间产物 `0.wav` 5.68s、`0-trim.wav` 1.73s），
成片气口噪底 -77.5dBFS / 峰 -48.3dBFS，末段后为数字静音。

### ② 忽大忽小：短句噪底误判触发噪声封顶

`measureSegment` 用 `astats` 的 `at(0.12)` 取噪底。wav 帧是 4096 样本 = 93ms，
1.5s 的短句只有 17 帧，12% 位置落在**语音段中间**，读到 -29dB；
`GAIN_NOISE_CEIL - floor` 于是把该句增益从 +3.4dB 砍到 -8.4dB，比邻句轻 11dB。
这与「逐句 LUFS 归一」本身没错，是噪底判据错。

改法：`asetnsamples=n=1024`（23ms 帧，1.5s 有 64 帧），噪底改成
「低于语音 12dB 的帧的中位数，且至少 4 帧」；`segmentGain` 改为
`TARGET_SPEECH_DB(-15.5) - speech`，删掉 ±3dB 跨句台阶与 `prevGain`；
整轨出片前再 `normalizeTrack` 收口到 -18 LUFS（±6dB 内）。

实测（3 段中文、含 2.6s/2.2s 长停顿）：`cueLevels [-13.9, -12.9, -14.0]`，
句间差 **1.1dB**（修复前同一素材 11.2dB / 三档 -23.2、-12.8、-12.0）。

### ③ AI 读错：中文 language_id 把拉丁缩写按拼音念

Chatterbox 给 `language_id=zh` 时，模型看到 "AI" 会念成拼音的 "ai"（一声），
听起来像「哎」。字幕里写 "AI"、配音里念「哎」，中英混读全毁。

改法：新增 `speakableText(text, langId)`，中文/日文/韩文里把
**独立出现的全大写拉丁缩写**按字母名展开再送给引擎（AI → 诶艾 / エーアイ / 에이아이），
字幕仍用原文。正则是 `(^|[^A-Za-z0-9])(\d*)([A-Z]{1,})(?![A-Za-z0-9])`，
所以 `OpenAI`、`iPhone`、`TikTok`、`ChatGPT` 这类混成词不转，英文语种整段不转。

实测（同一句 4 种写法，`0-trim.wav` 时长）：`AI` 1.93s、`诶艾` 2.67s、
`人工智能` 2.92s —— 展开后的时长与 4 音节词同量级，确认被完整读出而不是被吞。
（ASR 回环无法验证发音，本机未装 whisper 引擎。）

### ④ 仍不连贯：长停顿被原样搬进成片，句内死气口也没收

3.9.29 把语段起点锚回原片位置、语段之间"沿用原片停顿"，原片 2.6s 的换气被原封不动
搬进成片 → 听感依旧一句一断；克隆句内的死气口（≥0.22s，|v|<1e-3）也留着。

改法：
- 布局改为**连续语流**：`pauses[i] = clamp(原片 gap, 0.12, 0.5)`，语段顺次接排，
  只有首段起点仍对齐原片（≤0.2s）；
- `tightenPauses` 把句内 ≥0.22s 的死气口折叠到 0.14s，语音样本一个不动；
- 整片一次 `atempo`：`MIN_TEMPO 0.90`、`MAX_TEMPO 1.20`（放慢也真的执行，
  原来 `tempo>1` 才变速），还放不下才按比例压缩气口到 0.08s，硬上限 1.35。

实测：14s 片长、3 段中文，`tempo 0.900`，语音连续排布 0–7.15s，
`holes: []`（无 ≥0.6s 硬静音洞）。

### 附带修复：单段任务必定失败

`filter_complex` 拼接时单输入写成 `[a0],atempo=0.900`，中间多出一个空滤镜名，
ffmpeg 直接报 `No such filter: ''`，整条任务退出。现在单段走 `[a0]${post}`，
多段才 `amix=...:duration=longest,${post}`。单段 E2E 已通过（`units 1 / tempo 0.900 /
holes []`）。
